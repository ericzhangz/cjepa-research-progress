# Stage C Step 1：固定履历的 H12 候选覆盖对照

2026-11-18 · 官方原门位 FourRoom，静止背景 · 训练中的候选数 2→8，评估候选不变

## 预先指定的归因

前轮无标签组在名义两方案上 12/12、无关改选 2/48，但 384 候选真实写入遗憾为 75.52。候选 115 在真实轨迹和实际窗一步下都受阻，自由 H12 的预测却偏离实际窗约 73 px，获评分优势。先单独检验训练候选覆盖是否压低这种自由递推误差。西北与东南分别固定一种物理条件到解释的排列，另保留反排列，诊断去掉跨方位配对错误后仍有多少预测遗憾。局部排列仅作诊断，不进入训练和部署评分。

保持原 48 个 AAB/ABB 配对组及 96 个读根、真实控制和前缀、原二方案及其真后果、1,280 步及随机组选择、原参数化及初始化、训练目标、§49 有界支持、历史数据划分和部署规则。固定 H1 证据和 H12 目标的尺度为旧名义方案口径。新方案改变每次更新看到的轨迹数和计算量，不能解释为等 FLOP。冻结编码器；不将门锁标签、XY 探针或候选物理代价喂给拟合。物理坐标只用于构造符合覆盖条件的训练菜单和评价。

覆盖配额：在拟合根原候选库中，每个有条件差的读根至少选到一条在两条件下全轨一致且真实受阻的路径、两条件各一条非名义且真实可达的绕行；其余按固定随机顺序填满。共同后果在两种排列下总预测误差相同，不给解释贴标签。原中性读根用实际执行的短幅往返扩充，核对两条件下的整个后继逐值相等。随机初抽仅在 1/16 个不同的有条件差拟合根命中共同受阻，未进入模型训练。正式覆盖 64/64 次有条件差的拟合读根，192 条新增中性方案逐值共用真实目标，原数组及头两个候选逐值未变。采集 1,152 条 H12 物理程序。见 [覆盖计划](coverage_protocol.json) 和 [数值核验](coverage_data_audit.json)。

固定面板预定比较：旧错误首选的 H5/H12 自由窗减实际窗位置误差，24 个同根同库读出的首块物理遗憾及两方位局部排列上界诊断，保留 12/12、无关改选不超过 2/48。目标为每方位接近 Oracle  2.81（优先以低于 10–15 验证是否达到所需量级）。评估根是适合逐例匹配的历史留出根，不能当作新的独立确认。
