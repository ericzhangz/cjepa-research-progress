# 原生 FourRoom 同预算规划小试

此协议复用 [Gate 0 的反转腿](../physical_topology_gate_20261115/PROTOCOL.md)。预留 2026111900–2026111907 八个新布局，每个布局执行两种初始模式。共同脚本先实际试探，退回并远离门区，离墙换锁，再实际试探并返回同一站点。从该站点开始评估 12 块内首次进入目标半径 16。脚本控制器使用真实位置反馈生成同样的动作规则，真实坐标同时用于成功评分。规划小试的范围是这条配对反转腿。

每次规划使用 H5、四轮 CEM、每轮 96 候选、两个分量各取 12 条精英。每一模型臂根据自己预测的末端评分迭代提议。分量初始均值来自可见地图的两个方向，并由最新到达的完整 RGB 编码经共享冻结读出得到起点。门的可见位置和任务目标坐标为共享规划输入。凝缩末端评分与物理 Gate 0 的可见门中心路径代价相同。每个正式候选包含五个块，各块连续执行同一五次二维控制。预测阶段的假想动作不会改变真实支持或适应状态。

| 臂 | 学习与规划读法 |
|---|---|
| Stock | 官方冻结预测器，共用读出和 CEM |
| Native | 同离线预算单模式拟合的预测器 |
| Uniform | 固定条件模型，两模式代价各半 |
| Keep-Old | 固定条件模型，沿用前次真实试探结束时推断的 MAP |
| Persistent | 固定条件模型，用实际执行前发出的两项预测和到达 RGB 更新当前支持 |
| Oracle | 固定条件模型，读取当前真模式 |
| AdaJEPA | 从同预算 Native 开始，用作者适配器，ρ=0 |
| OpTTA | 从同预算 Native 开始，用作者适配器，ρ=1 |

Persistent 每个真实块应用 0.01 的对称转换先验。等到三个真实帧到达才形成第一个新似然，随后使用同一个校准尺度打分。Keep-Old 在换锁前封存旧事实得到的模式。Oracle 的实验标签只在选择条件代价时使用。

两个在线适配臂使用作者适配器的最后预测块、末归一化和预测投影更新，学习率 5e−5，每个实际块更新一次，缓存最近五个真实段，冻结编码和位置读出。OpTTA 使用前一次真实发出规划中最后一轮的 96 条候选作为乐观项。脚本动作没有前次候选，因此其真实到达只形成预测损失。作者的强度调度按已完成的实际更新计数，因此到首个计划可参与乐观项时已达到 ρ=1。从同一拟合参数出发，每个任务后恢复适配前权重。

已核对 192 个位置上的 NumPy 与 Torch 评分和有限 Torch 梯度，四轮合计 384 候选，并从历史物理结果复核了六个 H4–H6 首计划的选择与控制。原生 Oracle 与真实过程台阶裁定后，先用固定首个布局执行所有臂的软件检查，再执行其余七个。两部分均纳入结果。H5 比离线四块预测监督多一步。此前物理 Gate 0 的绝对真模式 80% 检查仍未达到，本小试用于观测当前预测能否进入同预算闭环。入口为 [native_topology_mpc.py](../../research/p1a/native_topology_mpc.py)。
